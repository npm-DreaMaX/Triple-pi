Feature 01

Persistent Memory 跨会话持久记忆

Coding agents 什么都不记得？Triple-pi 在会话之间记住用户偏好、决策、规则、事实与知识，并在每次提交前用这些规则审查改动。

🧠

SaveMemory / SearchMemory

明确要求时保存，展示全文并确认后才写入。SearchMemory 支持关键词检索项目/全局记忆，也支持检索临时 Working State。

  • 5 个分类：preference / decision / rule / fact / knowledge
  • 2 个作用域：project（默认） / global（所有项目）
  • 每条记录携带 provenance.evidence（用户原话引用）
  • LLM 捏造证据 → 候选直接拒绝
provenance.evidence fail-closed 原子写
⚙️

6 阶段自动提取管线

任意一环可拒绝，fail-closed 保证抽取质量。从脱敏到事务提交，每一步都防篡改、可追溯。

  • 01 脱敏 — 10 类常见密钥正则扫描
  • 02 LLM 提取 — 复用 Pi ModelRegistry
  • 03 严格校验 — schema + evidence 逐字命中 + 二次脱敏
  • 04 Grounded Review — 二次 LLM，只允许 keep/remove
  • 05 信号评分 — 指纹去重，Jaccard≥0.72 视为重复
  • 06 事务提交 — 写锁内 temp→rename 原子写

Feature 02

Project-aware Code Review 项目感知代码审查

提交前必须调用。自动 git diff + Memory 检索 → 只读 Reviewer 会话 → 严格 schema 校验 → 前后 worktree 快照对比。

🔍

review_current_changes

自动收集 staged + unstaged + untracked 变更，提取搜索词后检索相关记忆，用项目规则审查每一个 diff 分片。

  • collectGitChanges → extractReviewSearchTerms → searchRelevantMemories
  • buildReviewChunks（每 12KB 一片）→ 只读 Reviewer → strict parse
  • 大 diff 报告 coverage=partial，跳过文件显式列出，不静默省略
delegate_review 手动传入 分片透明
🔒

代码级只读保证

不是 prompt 约束，而是代码层面无法写入。会话以 noExtensions / noSkills / noContextFiles 创建，工具白名单仅 read/grep/find/ls。

  • 工具白名单仅 read / grep / find / ls（写工具不存在）
  • strict schema 校验：passed 必须有 0 findings，issues_found 必须 ≥1 findings
  • JSON 解析失败绝不报告为"无问题"

Comparison

常见做法 vs Triple-pi

不在 prompt 层面"许愿"，而在代码层面"保证"。

维度 常见做法 Triple-pi
记忆持久性 会话结束即丢失，每次重新解释需求 跨会话持久记忆，hot/cold/archived 生命周期
证据溯源 无 provenance，无法验证记忆来源 provenance.evidence 逐字引用用户原话，LLM 捏造即拒绝

Architecture & Storage

存储布局与生命周期

entry 为权威数据，MEMORY.md 为可重建的派生索引，revisions 为不可变快照。Working State 物理隔离。

📁 ~/.triple-pi/memory-v1/

memory-v1/ ├── entry/ ← 权威数据（不可变） │ ├── mem_2024_001.json │ ├── mem_2024_002.json │ └── mem_2024_003.json ├── MEMORY.md ← 可重建的派生索引 ├── revisions/ ← 不可变快照 │ ├── snapshot_001.json │ └── snapshot_002.json ├── working-state/ ← 临时状态（物理隔离） │ ├── scratchpad/ │ │ └── 2024-01-15.json │ └── daily/ │ └── 2024-01-15.md └── manifest.json ← 最后发布

Working State（Scratchpad/Daily）确定性生成，不调 LLM，标注 derived/temporary/untrusted。

🔄 记忆生命周期

🔥
hot < 30 天
正常注入，无需确认
❄️
cold 30–90 天
注入前询问用户确认
📦
archived > 90 天
无损归档，可执行 /memory-restore 恢复

scope 确定性解析：LLM 标记 global 但无跨项目证据（如"所有项目/跨项目"）→ 自动降级 project。
